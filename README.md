# Гибридное квантовое машинное обучение: табличные данные и изображения

Модель на PyTorch с **8 кубитами**, симулируемыми PennyLane `default.qubit`
через вектор состояния из 256 комплексных амплитуд. Классические полносвязные
слои находятся и до, и после квантового блока. Квантовый блок можно обойти,
не меняя размеры слоёв и не теряя обученные веса.

Отдельный ноутбук для MNIST, Fashion MNIST и CIFAR-10 поддерживает матрицу плотности
с шумами T1/T2, идеальный state vector и синхронное распараллеливание обучения на CPU.

## Опциональная стратифицированная k-fold кросс-валидация

В секции 4 ноутбука включите **Stratified k-fold кросс-валидация**, выберите `k`
и `CV val`. Можно указать один или несколько seed. Без флажка работает прежний
holdout. Секция 3 по-прежнему обучает один holdout-этап; CV запускается секцией 4.

- `StratifiedKFold(shuffle=True)` создаёт `k` внешних test-фолдов: каждый объект
  попадает во внешний test ровно один раз на seed и этап.
- Из оставшейся внешней train-части выделяется стратифицированный validation.
  `CV val=0.15` означает 15% **от этой оставшейся части**; обычная test-доля
  не используется — test определяется `k`.
- В каждом фолде создаются новые веса и своя предобработка. Scaler и медианы
  обучаются только на train. Перенос весов между этапами разрешён только внутри
  этого фолда. Между фолдами веса и обученная предобработка не переносятся.
- `fixed` оставляет внешние фолды и внутренний validation одинаковыми между seed;
  `vary` пересоздаёт их по seed повторения.
- Лучшие веса выбираются по внутреннему validation loss. Внешний test служит
  оценке фиксированного протокола; это не nested-поиск гиперпараметров.

Метрики каждого фолда сохраняются отдельно. Итог на seed — **OOF-метрики по всем
внешним test-предсказаниям**, где каждый объект представлен один раз. Accuracy
учитывает реальные размеры фолдов, macro-F1 вычисляется по общим OOF-предсказаниям,
а не усредняется по фолдам. Веса фолдов не усредняются и «лучший фолд» не выбирается.
CV-серия оставляет текущую одиночную модель ноутбука для предсказаний. При необходимости
загрузите checkpoint конкретного фолда явно или обучите отдельную финальную модель.

Фолды имеют пересекающиеся train и зависимы. Поэтому SD между фолдами выводится
только как описательная статистика, без SEM/CI. Итоговые mean/SD и приблизительный
t-CI OOF-метрики считаются по seed: **n = число seed, а не seed × k**. При одном seed
итоговая OOF-метрика есть, но SD/SEM/CI по seed не определены. CI при `fixed` условен
на данном датасете и наборе фолдов; неопределённость новых объектов он не оценивает.
При `vary` SEM/CI по-прежнему не выдаются. Кривые сначала усредняются по доступным
фолдам внутри seed, затем по seed; число доступных фолдов экспортируется отдельно.

Можно использовать JSON из ноутбука или включить CV для ранее экспортированного
протокола из терминала. Для изменённого протокола укажите новую папку:

```powershell
.\.venv\Scripts\python.exe scripts/run_seeds.py run --config study_config.json --seeds 11,22,33 --folds 5 --cv-val-size 0.15 --output runs/sonar_cv5
.\.venv\Scripts\python.exe scripts/run_seeds.py collect --inputs runs/sonar_cv5 --output runs/sonar_cv5/report_ci --band ci95
```

В CV-серии добавлены:

- `seed_<seed>/fold_XX/<этап>/` — веса, метрики, предобработка, аудит и тестовые
  предсказания `test_predictions.npz` каждого фолда;
- `report/per_fold.csv`, `fold_descriptive.csv` — метрики и описательный разброс фолдов;
- `report/oof_per_seed.csv` (также `per_seed.csv`) — итог на каждый seed;
- `report/oof_seed_<seed>_<этап>.csv` — OOF-предсказания с индексом строки после
  удаления дубликатов и вероятностями классов;
- `report/class_distribution.csv` — количества и доли классов для каждого seed/fold/этапа;
- `report/available_folds_per_epoch.csv` — фактическое число фолдов в кривых.

Сборщик проверяет наличие всех фолдов, отсутствие дублирования/пропусков тестовых
индексов, соответствие предсказаний метрикам и одинаковые разбиения между этапами.
Holdout и CV, разные `k`, разные данные и протоколы не объединяются в одну оценку.
Документация: [scikit-learn, stratified cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html).

## Несколько seed и точность с разбросом

В секции 4 ноутбука задаются список seed, протокол из одного или трёх этапов,
папка серии и тип полосы на графике: **SD** или **95% t-CI среднего**.
Каждый seed начинает с новой инициализации выбранной архитектуры; обученные
веса текущей одиночной модели не используются. Внутри seed этапы последовательно
переносят лучшие веса по validation loss. Пакет выполняется последовательно.

По умолчанию `split_policy="fixed"`: разбиение и предобработка одинаковы,
а seed меняет веса и порядок батчей. `split_policy="vary"` дополнительно меняет
разбиение и заново обучает предобработку только на соответствующем train.

Для метрики `a` по `n` seed выводятся:

- среднее `mean(a)` и выборочное стандартное отклонение `SD`, `ddof=1`;
- при фиксированном разбиении — `SEM = SD / sqrt(n)` и приблизительный 95% t-CI
  среднего: `mean ± t(0.975, n−1) × SEM`;
- при `n=1` SD/SEM/CI отсутствуют, а не равны нулю;
- при меняющихся, перекрывающихся разбиениях — описательные mean/SD без SEM/CI.

Пример формулировки: «На фиксированном test, split seed 42, accuracy = X%, SD = Y
процентных пунктов, n = 10 независимых seed обучения; приблизительный 95% t-CI
среднего по seed [L%, U%]». SD описывает разброс запусков, CI — оценку среднего
по случайности обучения. Это **не погрешность истинной accuracy на новых объектах**:
неопределённость от выбора конечного test такая оценка не учитывает.
T-интервал предполагает независимые запуски и применимость нормальной модели
для их метрик; при малом числе seed он особенно приблизителен. Формула:
[NIST, Confidence Limits for the Mean](https://www.itl.nist.gov/div898/handbook/eda/section3/eda352.htm).
Выбирайте seed и протокол заранее, желательно 5–10 или больше seed;
не отбирайте лучший seed и не настраивайте модель по test.

Конфигурация серии экспортируется ячейкой ноутбука в `runs/notebook_configs/` даже
при выключенном флажке обучения. Путь выводится в ячейке. С ним можно запустить
все seed вместе или добавлять их по одному из терминала:

```powershell

В ноутбуке есть аналогичная секция сбора папок без обучения. Разные датасеты,
архитектуры, режимы разбиения, гиперпараметры и версии вычислительных библиотек
не объединяются. Дубли seed в разных папках отклоняются; одна и та же папка,
указанная повторно, учитывается один раз. После прерванного seed его незавершённая
папка не входит в отчёт; перезапуск для неё требует новой папки серии.
При переносе того же датасета можно указать `--data новый/путь.csv`: проверяется
fingerprint содержимого. Запускать команды следует из корня проекта.

Артефакты серии:

- `study.json`, `config.json` — фиксированные данные, архитектура, split policy и протокол;
- `seed_<seed>/<этап>/` — отдельные checkpoint, метрики и история каждого этапа;
- `seed_<seed>/run.json` — признак успешного завершения всего протокола;
- `report/per_seed.csv` — метрики всех seed, размеры выборок и пути к весам;
- `report/summary.csv`, `summary.json`, `report.txt` — mean, SD, SEM, CI и пояснение;
- `report/metrics_spread.png/.svg` — точки seed и среднее с усами;
- `report/learning_curves_<этап>.png/.svg`, `curves_<этап>.csv` — кривые с полосой
  и число доступных seed на каждой эпохе.

При early stopping кривые агрегируются по доступным запускам, без продления
завершённых кривых. Поэтому состав запусков на поздних эпохах может меняться:
число `n` сохраняется в таблице кривых, и поздние средние нельзя считать средним всех исходных seed.

[DOI 10.24432/C5T01Q](https://doi.org/10.24432/C5T01Q), лицензия CC BY 4.0.

```

## Архитектура

Ниже приведены значения по умолчанию; ноутбук позволяет менять их.

```text
Числовые признаки (Dry Bean: 16)
    ↓ медиана пропусков + StandardScaler, обученные только на train
Linear(n_features, 32) → ReLU → Linear(32, 8) → tanh
    ↓
Квантовый блок на 8 кубитах ИЛИ тождественный обход 8 → 8
    ↓
Linear(8, 16) → ReLU → Linear(16, n_classes)
    ↓
Logits → CrossEntropyLoss при обучении / softmax при предсказании
```

Всего **4 классических полносвязных слоя**. В квантовом блоке входы `z ∈ [-1, 1]^8`
кодируются вращениями `RY(πz_i)` состояния `|0⟩⁸`. Каждый вариационный слой
содержит обучаемые `RY` и `RX` на каждом кубите, затем кольцо последовательных
CNOT: `0→1, 1→2, …, 6→7, 7→0`. Выход — восемь ожиданий `⟨Z_i⟩ ∈ [-1, 1]`.
Глубина по умолчанию 2, то есть **32 квантовых параметра**. Измерения аналитические
(`shots=None`), градиенты вычисляются через `backprop`, включая производные по входам схемы.
Запуск настроен на CPU. Квантовое оборудование не требуется.

## Три независимых переключателя

| Параметр CLI | Значение |
|---|---|
| `--quantum` / `--no-quantum` | Использовать схему / пропустить её |
| `--train-classical` / `--no-train-classical` | Обучать / заморозить **оба** классических блока |
| `--train-quantum` / `--no-train-quantum` | Обучать / заморозить параметры квантовой схемы |

Для новой модели все три включены. При загрузке checkpoint значения наследуются;
переданные флаги переопределяют их. Если схема выключена, квантовые параметры
сохраняются, но не участвуют в вычислениях и обновлении. Когда все активные параметры
заморожены, команда `train` выполняет только оценку без оптимизации.

Заморозка использует `requires_grad_(False)`. Замороженная схема продолжает
передавать градиент к encoder, а замороженный классификатор — к схеме.
При смене режима в Python нужно пересоздать оптимизатор; `fit` делает это автоматически.

## Поэтапное обучение

При первом запуске датасет автоматически скачивается с UCI в `data/`.
Можно заранее выполнить `python -m qml_beans download`.
Все команды ниже выполняются Python из виртуального окружения:

```powershell
# 1. Обучить классические блоки с обходом квантовой схемы
.\.venv\Scripts\python.exe -m qml_beans train --no-quantum --epochs 30 --output runs/classical

# 2. Подключить схему, заморозить классические блоки, обучать только квантовую часть
.\.venv\Scripts\python.exe -m qml_beans train --checkpoint runs/classical/best.pt --quantum --no-train-classical --train-quantum --epochs 10 --output runs/quantum_only

# 3. Совместно дообучить обе части
.\.venv\Scripts\python.exe -m qml_beans train --checkpoint runs/quantum_only/best.pt --quantum --train-classical --train-quantum --epochs 20 --lr 0.0003 --quantum-lr 0.001 --output runs/joint

# Альтернатива: обучать классическую часть через фиксированную квантовую схему
.\.venv\Scripts\python.exe -m qml_beans train --checkpoint runs/classical/best.pt --quantum --train-classical --no-train-quantum --epochs 20 --output runs/fixed_quantum

# Гибридная модель с нуля — отдельный эксперимент
.\.venv\Scripts\python.exe -m qml_beans train --quantum --epochs 30 --output runs/hybrid_scratch
```

Выход схемы отличается от тождественного обхода. Поэтому при подключении схемы
точность может сначала упасть: предварительное обучение классики не гарантирует
удачную инициализацию гибрида. Этап совместного дообучения позволяет адаптировать
оба классических блока. Возможность обучать только квантовую часть предусмотрена
для эксперимента, но сама по себе не гарантирует восстановления качества.

Каждая команда начинает **новый этап** с новым Adam; checkpoint переносит веса,
режим, классы, предобработку и разбиение, но не состояние оптимизатора или генераторов
предыдущего этапа. `--seed` задаёт воспроизводимость нового этапа. Архитектуру при
продолжении менять нельзя. Для других данных следует создать новую модель.

При желании все три этапа можно запустить скриптом:

```powershell
.\.venv\Scripts\python.exe scripts/run_stages.py --output runs/experiment --classical-epochs 30 --quantum-epochs 10 --joint-epochs 20
```

## Данные и оценка

[UCI Dry Bean](https://archive.ics.uci.edu/dataset/602/dry+bean+dataset):
13 611 строк, 16 числовых признаков, 7 классов. Используются готовые признаки,
а не изображения бобов. Источник: *Dry Bean [Dataset]*, 2020,
[DOI: 10.24432/C50S4B](https://doi.org/10.24432/C50S4B), лицензия CC BY 4.0.

По умолчанию точные дубликаты строк удаляются **до** разбиения, чтобы одинаковые
примеры не попали одновременно в train и test. При одинаковых признаках и
противоречащих метках программа просит исправить данные. `--keep-duplicates`
отключает эту защиту и допускает утечку дубликатов между выборками.

Разбиение стратифицированное: **65% train / 15% validation / 20% test**, `seed=42`.
Медианы пропусков и параметры StandardScaler вычисляются только на train.
Лучшие веса и early stopping выбираются по validation loss. Test используется
только для итоговой оценки выбранных весов каждого этапа. Не подбирайте по нему
глубину, число эпох или лучший эксперимент. Для содержательного сравнения моделей
нужны одинаковые разбиения и несколько seed; преимущество квантовой модели не предполагается.

В каждой новой папке запуска:

- `best.pt` — веса с минимальным validation loss, включая начальное состояние (эпоха 0);
- `last.pt` — веса последней выполненной эпохи;
- `metrics.json` — accuracy, balanced accuracy, macro-F1, матрица ошибок и метрики по классам;
- `history.json`, `history.csv` — история обучения (CSV при наличии эпох);
- `data_metadata.json` — признаки, классы, параметры предобработки, индексы выборок и fingerprint.

Порядок строк и столбцов матрицы ошибок совпадает с `classes` в JSON: строки —
истинные классы, столбцы — предсказанные. Исходный датасет не сохраняется в checkpoint;
для продолжения или повторной оценки нужен тот же CSV/ARFF. Проверяется fingerprint
содержимого, порядка строк и схемы. Для новых объектов используется команда `predict`.
Существующие папки экспериментов с результатами не перезаписываются.

### Число измерений (shots)

В обоих ноутбуках есть поля **«Измерений (shots)»** и **«Seed измерений»**.
Значение `0` включает аналитический режим (`shots=None`).
Например, `1024` включает 1024 измерения на объект, а оценка Pauli Z равна
`(N0 - N1) / 1024`. Все восемь кубитов измеряются совместно: один набор битовых
строк даёт восемь средних с сохранением корреляций между кубитами. Для X/Y
используется соответствующий базис измерений. Это статистика измерения конечного
состояния, отдельная от физических каналов T1/T2.

Конечные shots работают на `torch_density`, `pennylane_mixed` и
`pennylane_statevector`, а также в табличном state-vector пайплайне.
В обоих ноутбуках поле **«Режим измерений»** задаёт `ModelConfig.measurement_mode`:

| Режим | Во время обучения | При валидации и тестировании |
|---|---|---|
| `sampled_backprop` | Совместные конечные shots на входе головы; аналитический Jacobian квантового среднего | Конечные shots |
| `analytic_train` | Аналитические средние и обычный backprop | Конечные shots |
| `parameter_shift` | Конечные shots и выборочный parameter-shift | Конечные shots |

При `shots=None` все режимы аналитические. Значение `parameter_shift` остаётся
режимом по умолчанию для совместимости старых конфигураций; текущие значения
остальных виджетов при добавлении переключателя сохраняются.

`sampled_backprop` выполняет одну аналитическую симуляцию состояния, выбирает реальные
совместные битовые строки и сохраняет точные значения выборочного forward. В backward
градиент проходит через точное среднее. Это эквивалентно
`mu + (sampled_mu - mu).detach()` по градиенту; отдельная autograd-функция позволяет
избежать численной погрешности вычитания в значениях forward.
**Это суррогатный градиент**, в общем случае смещённый относительно градиента
математического ожидания нелинейной конечной-shot функции потерь.
Аналитический граф сохраняет производные входных углов и весов при повторном
кодировании; замороженная квантовая часть продолжает передавать градиент энкодеру.

В `analytic_train` выбор определяется `model.train()` / `model.eval()`, независимо
от `torch.no_grad()` и наличия обучаемых параметров. Сборщики обучения переключают
фазы и в основном процессе, и в CPU-работниках. Валидация для early stopping также
использует конечные shots, поэтому её метрика может колебаться. При явном запросе
градиента в eval-режиме используется аналитический Jacobian; обычная оценка идёт
в `no_grad()`. Физическая эволюция T1/T2 учитывается и при обучении, и при оценке.

В `parameter_shift` PyTorch реализует сдвиги по отдельным вхождениям вентилей,
включая все повторные кодирования. Он оценивает квантовый Jacobian; после нелинейной
головы это само по себе не гарантирует несмещённости градиента всей конечной-shot
функции потерь. Оба новых режима избегают запусков сдвинутых квантовых схем.

Каждая сдвинутая схема также использует заданное число shots. Поэтому стоимость
обучения может существенно вырасти с глубиной и числом параметризованных вентилей.
В симуляторе parameter-shift обычно медленнее аналитического backprop; сначала
проверьте небольшую подвыборку. Микробатчи ограничивают память, но не число сдвигов.

Случайность управляется отдельным seed измерений. CPU-задачи получают разные
детерминированные подпотоки; для повторения полного запуска сохраняйте число
процессов, режим разделения батча, микробатч и порядок вычислений. При повторной
оценке тех же весов результат может меняться из-за shot noise. Настройки shots
и seed измерений, а также `measurement_mode` включены в конфигурацию модели,
checkpoint, метрики и проверку совместимости серий. Разные режимы не объединяются
в одну статистику. Старые checkpoint без shots остаются аналитическими; сохранённые
shots без `measurement_mode` продолжают использовать прежний `parameter_shift`.

Пример API: `ModelConfig(n_features=196, n_classes=10, shots=1024, measurement_seed=42)`.
В Python API аналитический режим — `shots=None`; в виджете и CLI ему соответствует `0`.

```python
from qml_beans.model import ModelConfig
from qml_beans.noisy import NoisyHybridClassifier, NoiseConfig

# 1. Выборочный forward с аналитическим Jacobian
config = ModelConfig(n_features=196, n_classes=10, shots=1000,
                     measurement_mode="sampled_backprop")

# 2. Аналитическое обучение; конечные измерения в eval
config = ModelConfig(n_features=196, n_classes=10, shots=1000,
                     measurement_mode="analytic_train")
model = NoisyHybridClassifier(config, NoiseConfig())
model.train()  # точные средние, backprop
model.eval()   # 1000 shots на объект
```

### Выбор бэкенда

- `torch_density` — специализированный дифференцируемый симулятор матрицы плотности на PyTorch.
  Локальные каналы применяются непосредственно к блокам матрицы, без построения больших
  полных матриц операторов или выборки случайных траекторий.
- `pennylane_mixed` — `default.mixed`, `ThermalRelaxationError`, аналитические или конечные измерения.
  Это эталон для проверки выходов и градиентов, доступный и для обучения.
- `pennylane_statevector` — идеальный `default.qubit` без T1/T2, для сравнения с шумовой моделью.
  При выборе в виджете шум отключается, введённые T1/T2 сохраняются. При возврате к матрице
  плотности восстанавливается прежнее включение шума. В Python API требуется `enabled=False`;
  попытка включить T1/T2 для идеального state vector вызывает явную ошибку.

Варианты матрицы плотности используют одну структуру схемы и одинаковое расписание длительностей.
8 кубитов дают матрицу 256×256 на объект. PyTorch поддерживает комплексные состояния
complex64/complex128 при выборе float32/float64. PennyLane может повышать внутреннюю
точность до complex128 даже при float32 на входе; поэтому замер скорости учитывает
фактическую реализацию каждого бэкенда, а не обещает одинаковые внутренние типы данных.

Для каждого кубита задаются T1 и T2 (одно общее число либо 8 чисел), длительности
однокубитных и двухкубитных операций, задержка перед измерением. Всё в микросекундах.
Проверяется `0 < T2 <= 2*T1`. Нулевая температура: населённость возбуждённого уровня
затухает как `exp(-t/T1)`, когерентность — как `exp(-t/T2)`. Поэтому дополнительная
чистая дефазировка должна соответствовать `1/Tphi = 1/T2 - 1/(2*T1)`, а не `1/T2`.

Однотипные вращения восьми кубитов считаются параллельным временным интервалом;
двухкубитные вентили — последовательными. После каждого интервала канал применяется
ко всем кубитам, включая простаивающие. RZ имеет такую же настраиваемую длительность,
как RX/RY; виртуальные операции отдельно не выделены. Шум отключается флажком.
Это модель независимого марковского шума «операция, затем канал». Она не включает
конечную температуру, ошибки считывания, перекрёстные помехи или интегрирование
шума одновременно с управляющим импульсом. Точность относится к этой модели канала,
а качество классификации необходимо измерять на тесте.

### Данные и обучение

Сохраняется официальная тестовая выборка; стратифицированная валидация выделяется
только из официального обучения. Доступны исходные и уменьшенные изображения,
полный датасет или явно обозначенная стратифицированная подвыборка. По умолчанию
включена подвыборка для проверки настроек. Нормализация фиксированная: `pixel/127.5 - 1`.
Цветовые каналы CIFAR сохраняются. Индексы, идентификатор исходных данных и настройки
предобработки записываются в результаты.

Настраиваются полносвязные слои/нейроны/активации с обеих сторон квантовой части,
число квантовых слоёв, вращения, связи, кодирование и измерение. Сохраняются три
независимых переключателя: квантовая часть включена, классическая часть обучается,
квантовая часть обучается. Градиент проходит к энкодеру и через замороженную схему.
Для поэтапного обучения используйте одно начальное значение и `continue_current_model=True`.
Новый этап создаёт новый Adam; веса переносятся из лучшей модели прошлого этапа.

Ранняя остановка — по валидационной кросс-энтропии: `patience` эпох без улучшения
не менее `min_delta`; `patience=0` отключает её. Сохраняются `best.pt`, `last.pt`,
история JSON/CSV и метрики JSON. Официальный тест оценивается после выбора лучших
весов по валидации. Шумовые checkpoint загружает `load_noisy_checkpoint`.

Несколько начальных значений запускаются в одной серии или собираются из отдельных
папок функцией `report_vision_study`. Для независимых запусков веса инициализируются
заново, разбиение фиксировано. Сборщик проверяет совпадение протоколов и отсутствие
повторных значений; продолженное обучение не объединяется как независимые инициализации.
Графики на русском сохраняются в PNG/SVG со стандартным отклонением или условным
приближённым 95%-м ДИ среднего по инициализациям. Один запуск не даёт оценки разброса.
Новый ноутбук использует официальное разбиение с валидацией; k-fold остаётся доступной
в исходном ноутбуке для табличных данных.

### Параллельный CPU

`CPUConfig(workers=2, threads_per_worker=1, microbatch_size=2)` задаёт два процесса,
один поток вычислений в каждом, микробатчи из двух объектов.
`parallel_mode='split_batch'` делит общий батч между процессами; `'batch_queue'`
создаёт очередь нескольких микробатчей из общего батча.
Оба режима синхронны: все работники читают одни веса, считают суммы градиентов,
основной процесс делит их на общее число объектов и делает один шаг Adam.
Неравные части и последний неполный батч учитываются по числу объектов.
Увеличение числа процессов не меняет эффективный размер батча или частоту шагов.

Графы вычислений освобождаются после каждого микробатча. Веса и данные доступны
через общую память, функции работников вынесены из ячеек в импортируемый модуль
для совместимости с Windows spawn/Jupyter. Это несколько процессов одной машины.
Для параллельности внутри тензорных операций увеличьте `threads_per_worker`;
учитывайте произведение потоков на процессы и расход памяти на каждый граф backward.
Сначала измерьте 1/2/4 процесса: ускорение ограничивают память и обмен данными.

Измерить скорость выбранной конфигурации: `python scripts/benchmark_noisy.py`.
Скрипт создаёт `runs/noisy_backend_benchmark.csv` и описание конфигурации JSON.
Ноутбук содержит отдельную необязательную ячейку измерения на выбранных данных.

Проверки: физическое затухание T1/T2, след/эрмитовость/положительность матрицы,
совпадение с идеальным state vector при отключённом шуме, сравнение выходов и
градиентов с PennyLane, независимая конечная разность, неравные параллельные части
и эквивалентность шага Adam, все три формата изображений и checkpoint.
Для `T2>T1` эталонный Kraus-канал PennyLane вблизи нулевой равновесной
возбуждённости имеет небольшую регуляризационную погрешность; сравнение учитывает
численную погрешность порядка 1e-6, аналитический канал дополнительно проверяется отдельно.

Полное выполнение ноутбука на маленькой реальной подвыборке:

```powershell
.venv\Scripts\python.exe scripts/check_noisy_notebook.py --dataset MNIST --workers 2
.venv\Scripts\python.exe scripts/check_noisy_notebook.py --dataset "Fashion MNIST" --workers 2 --backend pennylane_mixed
.venv\Scripts\python.exe scripts/check_noisy_notebook.py --dataset CIFAR-10 --workers 2
```

Эти проверки используют по одной эпохе и 20 обучающих объектов; они проверяют
работоспособность, а не итоговое качество модели. Полноценное обучение датасетов
на десятках тысяч изображений следует запускать с выбранным вычислительным бюджетом.

Источники: [ThermalRelaxationError](https://docs.pennylane.ai/en/stable/code/api/pennylane.ThermalRelaxationError.html),
[MNIST, форматы и контрольные суммы](https://github.com/pytorch/vision/blob/main/torchvision/datasets/mnist.py),
[Fashion MNIST](https://github.com/zalandoresearch/fashion-mnist),
[CIFAR-10: описание и контрольная сумма бинарного архива](https://www.cs.toronto.edu/~kriz/cifar.html).
